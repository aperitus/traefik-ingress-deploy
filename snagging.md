# Snagging Log — Traefik Ingress Repo (Chat Summary)

This table collates the issues addressed per **iteration ID** during the iterative build of the **Traefik ingress** repo/workflow.

> Note: iteration IDs are for snag tracking only; they are **not** Git tags or release versions.  
Assumption applied: **if an error was not re-entered after a change, it is treated as corrected.**

| Iteration ID | Primary issue(s) observed | Error / symptom (as seen) | Fix / change applied | Outcome / notes |
|---:|---|---|---|---|
| I01–I03 | Strategy + repo split | N/A (design change) | Switched from ingress-nginx to **Traefik**; separated “Traefik foundation” from “Dependency-Track app”; internal-only ingress requirement captured; wildcard cert constraint clarified (`*.logiki.co.uk` does **not** cover `*.apps.logiki.co.uk`) | Foundation ingress deploys first; DTrack goes behind it later |
| I04–I05 | GHES action resolution + vars defaults + YAML syntax | GHES errors resolving `azure/login@v2`, `azure/setup-helm@v4`, `azure/setup-kubectl@v4`; workflow YAML syntax error around DNS step | “Option B”: rely on runner-installed `az/kubectl/helm`; moved operational inputs to `vars.*` with input overrides; fixed YAML structure/indentation; constrained environment selection direction | Workflow becomes GHES-compatible and cleaner to run |
| I06–I07 | Traefik chart schema + timeout + chart-vs-image | Chart schema failures: `imagePullSecrets not allowed`; `ports.*.expose` type mismatch; Helm timeout `"10"` missing unit; confusion between `traefik/traefik` vs `library/traefik` | Adjusted values template to match chart schema; added timeout normalisation; enforced chart source `traefik/traefik` and Nexus image override `library/traefik` | Removed schema/timeout blockers; clarified Nexus-only image sourcing |
| I08 | Gateway selector label type | Gateway API validation: `matchLabels.<key> ... must be of type string: "boolean"` | Forced selector values to strings (quoted / `--set-string`); guarded against boolean-like values | Gateway manifest validation stabilised |
| I09–I10 | Non-interactive auth + Entra-enabled AKS + DNS perms docs | Azure CLI prompted device code login; kubectl steps hung; DNS update in other subscription failed due to perms | Added SPN-based non-interactive login pattern; added `kubelogin convert-kubeconfig -l spn`; documented cross-subscription DNS permissions and required subscription id var | Eliminated interactive login path; clarified permission requirements |
| I11–I12 | Workflow syntax rewrite + dashboard check redesign | Workflow had syntax errors; kube-apiserver proxy/port-forward tests unreliable (`NotFound`, RBAC/proxy issues, connection refused) | Rewrote workflow cleanly; moved dashboard/API test to an **in-cluster Job** hitting a **ClusterIP** dashboard service; added debug toggle to upload generated values (assuming artifact action available) | Reduced runner networking/RBAC fragility; improved diagnostics |
| I13 | Helm render failure in Gateway template | Helm error: `traefik/templates/gateway.yaml ... error calling eq: incompatible types for comparison` | Disabled chart-managed Gateway rendering; apply `GatewayClass/Gateway` via `kubectl` in a separate step when Gateway mode enabled | Avoids chart template bug while keeping Gateway API mode |
| I14 | Bash heredoc expansion + unsuitable test image | `u: unbound variable` in runner script under `set -u`; test image lacked curl/wget | Escaped `\${u}` in heredoc so runner doesn’t expand it; documented `TRAEFIK_TEST_IMAGE` must include curl/wget and be Nexus-hosted | Dashboard test script stops failing at runner expansion stage |
| I15 | Traefik API reachable but returned 404 | In-cluster check: `/api/version` returned `404` | Explicitly enabled API/dashboard via `additionalArguments` (`--api=true`, `--api.dashboard=true`, `--api.insecure=true` internal-only); adjusted check to accept correct response patterns | API endpoint becomes available on internal dashboard service; check aligns with real behaviour |
| I16 | TLS default + HTTP→HTTPS redirect policy | Need consistent HTTPS default; HTTP-only routes would be broken once redirect is enabled | Set `enable_tls` default to `true`; enforced entryPoint redirect (`web` → `websecure`) when TLS enabled; updated BOM/prompt/onboarding docs to reflect Option B | TLS is the default stance; apps using Ingress must define `spec.tls` in their namespaces to avoid redirect-to-404/cert mismatch |
| I17 | TLS secret creation failed due to non-PEM secret contents | `tls: failed to find any PEM data in certificate input` then `no objects passed to apply` | Added fast-fail validations: PEM marker checks, `openssl` parse, keypair match; create Secret YAML to file then `kubectl apply` to avoid pipeline masking root error; documented local validation commands in `README.md` | Clearer diagnostics; prevents silent/secondary errors when secrets are base64/PFX/DER or mismatched key |
| I18 | False-negative PEM detection + need to capture TLS material handling | `grep: unrecognized option '-----BEGIN CERTIFICATE-----'` leading to erroneous "not PEM" failure | Fixed grep marker checks by using `--`/`-F`/`-E` so patterns starting with `-` are not treated as options; added a separate debug job gated by `debug_values=true` that uploads `wildcard.crt` + derived `wildcard.public.pem` and diagnostics (never the private key) | Removes misleading failures; enables inspection of the written certificate file when troubleshooting |
| I19 | Vars-first resolution + deploy debug bundle | Azure Private DNS step failed when record name missing; hardcoded `vars.*` vs `secrets.*` precedence made environments inconsistent; limited data when Helm failed | Standardised non-sensitive precedence to `inputs → vars → secrets`; added deploy debug artifact capturing Helm chart/metadata, `helm status/history/get-*`, `kubectl get/describe/events`, and Traefik pod logs; added required validation for `PRIVATE_DNS_A_RECORD_NAME` when DNS enabled | More deterministic config resolution; significantly better failure triage; avoids the CLI "missing --record-set-name" class of error |
| I20 | Action version compatibility | Platform constraint: must use `actions/upload-artifact@v3` (and avoid Node20-only action versions) | Set all artifact uploads to `actions/upload-artifact@v3` and aligned checkout to `actions/checkout@v3`, retaining the debug bundle contents and `if: always()` semantics | Meets GHES/supportability requirements without losing diagnostics |
